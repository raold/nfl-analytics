WHAT IS IT?
-----------
Conservative Q-Learning agent for automated feature selection in NFL analytics.
Learns optimal feature combinations from limited historical data while avoiding
overestimation on untested feature sets.

KEY INNOVATION: CQL PENALTY
---------------------------
Loss = TD_loss + α * (log Σ exp(Q(s,a)) - Q(s, a_data))
       ^^^^^^^^       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
       Standard       Conservative penalty
       Bellman        (penalizes untested actions)

Why CQL > DQN?
- Limited data: ~1000 games for validation
- High-dimensional: 232 features with exponential combinations
- Expensive evaluation: 1-3 hours per feature set
- Novel combinations: Most feature sets never tested

ARCHITECTURE
------------
State (243D):
  - Feature flags (232): Binary indicators for each feature
  - Performance metrics (10): MAE, calibration, ROI, win_rate, etc.
  - Budget indicator (1): Fraction of max features used

Action (600D):
  - Individual features (232): Toggle single feature
  - Feature groups (10): Toggle entire category
  - Pairwise interactions (350+): Add/remove interactions

Network:
  Input(243) → Linear(256) → LayerNorm → ReLU → Dropout(0.1)
            → Linear(256) → LayerNorm → ReLU → Dropout(0.1)
            → Linear(600) → Q-values

USAGE: TRAINING
---------------
from py.rl.cql_feature_selector import CQLFeatureSelector, train_cql_feature_selector

# Create agent
agent = CQLFeatureSelector(
    state_dim=243,
    action_dim=600,
    alpha=1.5,              # CQL penalty (1.5 = conservative)
    gamma=0.95,             # Discount factor
    lr=1e-3,                # Learning rate
    batch_size=64,
    hidden_dims=[256, 256],
    prioritized_replay=True
)

# Train on offline data

USAGE: INFERENCE
----------------
from py.rl.cql_feature_selector import CQLFeatureSelector

# Load trained agent
agent = CQLFeatureSelector.load("models/cql_feature_selector_v1.pth")

# Select optimal feature subset
feature_mask = agent.select_features(
    base_features=["feature_1", "feature_2", ...],  # All 232 features
    feature_budget=100,                              # Max features to select
    epsilon=0.0                                      # Greedy (no exploration)
)

# Extract selected features
selected = [f for f, m in zip(base_features, feature_mask) if m == 1]

HYPERPARAMETERS
---------------
alpha (CQL penalty):
  - 0.5: Less conservative (use if abundant data)
  - 1.0: Balanced (default for betting, proven)
  - 1.5: More conservative (default for feature selection)
  - 2.0: Very conservative (safety-critical)

lr (learning rate):
  - 1e-4: Slow, stable
  - 5e-4: Moderate
  - 1e-3: Fast (default)
  - 5e-3: Very fast (may be unstable)

hidden_dims:
  - [128, 128]: Small (faster, less capacity)
  - [256, 256]: Medium (default, balanced)
  - [512, 256]: Large (more capacity, slower)

prioritized_replay:
  - True: Prioritize high-reward/high-error transitions (default)
  - False: Uniform sampling (simpler, sometimes better)

TRAINING METRICS
----------------
loss:       Total loss (TD + CQL penalty)
td_loss:    Temporal difference loss (Bellman error)
cql_loss:   CQL penalty (conservatism measure)
q_mean:     Average Q-value (should stabilize)
q_std:      Q-value standard deviation (uncertainty)
lr:         Current learning rate (from scheduler)

Target convergence:
  - Epoch 1:   Loss ~10-15, CQL ~4-5, Q_mean ~0
  - Epoch 50:  Loss ~2-3,   CQL ~1-2, Q_mean ~0.5
  - Epoch 100: Loss ~1-2,   CQL ~0.2-0.5, Q_mean ~0.5

COMMON ISSUES
-------------
1. CQL penalty not decreasing
   → Reduce alpha (try 0.5-1.0)
   → Increase lr (try 5e-4)
   → Check dataset quality

2. Q-values exploding
   → Reduce lr (try 1e-4)
   → Increase gradient clipping (max_norm=5.0)
   → Clip rewards to [-10, 10]

3. Feature selection too conservative
   → Reduce alpha (try 0.5-1.0)
   → Increase epsilon (try 0.1-0.2)
   → Warm-start with proven features

4. Feature selection not diverse
   → Increase epsilon (try 0.2-0.3)
   → Use softmax action selection
   → Diversify training data
