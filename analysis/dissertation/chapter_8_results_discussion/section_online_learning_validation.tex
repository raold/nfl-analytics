\section{Online Learning Validation - Preliminary Results}
\label{sec:online-learning-validation}

\textbf{Status:} Preliminary implementation completed but validation revealed critical failures requiring debugging before production deployment. This section documents empirical results, failure analysis, and path forward with research integrity.

This section evaluates our online learning framework on the 2024 NFL season, testing four hypotheses:

\begin{enumerate}
    \item \textbf{Prequential performance}: Online models adapt to seasonal trends (target: within 5\% of static baseline)
    \item \textbf{Drift detection accuracy}: Multi-detector ensemble (ADWIN + KSWIN + Page-Hinkley) identifies known events with 90\%+ F1 score
    \item \textbf{Adaptation speed}: Recovery time <5 games after distributional shifts
    \item \textbf{ROI improvement}: Online learning provides positive ROI lift vs static baseline
\end{enumerate}

\noindent \textbf{Validation Outcome:} All four hypotheses rejected. Online learning model underperforms static baseline by 3.5×, drift detection achieves 0\% precision/recall, and no measurable ROI improvement observed.

\subsection{Experimental Setup}

\subsubsection{Dataset}

We validate on the 2024 NFL regular season passing yards:

\begin{itemize}
    \item \textbf{Season}: 2024 (Weeks 1-18)
    \item \textbf{Total records}: 532 player-game passing performances
    \item \textbf{After feature engineering}: 121 records (77\% dropped due to insufficient lag history)
    \item \textbf{Unique passers}: 110 quarterbacks
    \item \textbf{Features}: 5 lag features (passing\_yards\_L3, L5, L10, completions\_L3, attempts\_L3)
    \item \textbf{Target}: Passing yards per game
\end{itemize}

\noindent \textbf{Critical Data Issue:} Only 121 usable records (23\% of original 532) after dropna() suggests aggressive lag feature requirements. With 3/5/10 game rolling windows, many QBs lack sufficient history—particularly rookies, backups, and early-season games.

\subsubsection{Model Configuration}

\begin{itemize}
    \item \textbf{Online model}: Adaptive Random Forest (10 base trees, River library)
    \item \textbf{Drift detectors}: ADWIN, KSWIN, Page-Hinkley (multi-detector ensemble with medium sensitivity)
    \item \textbf{Warm-up window}: 50 games
    \item \textbf{Static baseline}: Simple mean predictor (historical average passing yards)
\end{itemize}

    \item Validate detector sensitivity on controlled data before NFL deployment
\end{itemize}

\subsection{Failure Analysis: Root Causes}

\paragraph{1. Data Leakage in Lag Features}
The primary suspect is temporal data leakage in feature engineering. Lag features (passing\_yards\_L3, L5, L10) may incorrectly use `.shift(0)` instead of `.shift(1)`, allowing future information to leak into training. This would explain:
\begin{itemize}[nosep]
    \item High variance (std MAE = 2,577 yards) - model overfits to leaked data
    \item Poor generalization (MAE = 535 yards) - leaked features don't transfer
    \item Missing samples (77\% dropped) - incorrect rolling window logic
\end{itemize}

\paragraph{2. Insufficient Training Data}
Only 71 samples in final model is catastrophically low for online learning:
\begin{itemize}[nosep]
    \item River library Adaptive Random Forest requires $>200$ samples for stable trees
    \item Drift detectors need $>500$ samples to distinguish signal from noise
    \item Expected 19,000+ samples (285 games × 2 QBs × 18 weeks), got 71 (0.37\%)
\end{itemize}

\paragraph{3. River Library Configuration Issues}
Adaptive Random Forest may require tuning for NFL sparse data:
\begin{itemize}[nosep]
    \item Default hyperparameters (n\_models=10, max\_depth=None) may overfit
    \item Grace period, drift threshold, warning level may need adjustment
    \item Alternative: Try Hoeffding Adaptive Tree or ARFC (Adaptive Random Forest Classifier)
\end{itemize}

\subsection{Path Forward: Debugging Protocol}

\paragraph{Immediate (High Priority)}
\begin{enumerate}[nosep]
    \item \textbf{Audit data pipeline}: Verify all `.shift()` calls use correct offsets, validate rolling window logic
    \item \textbf{Validate on 2020-2023 seasons}: Test against known drift events (COVID-19, 17-game season)
    \item \textbf{Synthetic data testing}: Inject controlled drift (e.g., +50 yards in Week 8), verify detectors fire
    \item \textbf{Feature count investigation}: Why only 121/532 samples survive dropna()? Relax lag requirements
\end{enumerate}

\paragraph{Medium-Term}
\begin{enumerate}[nosep]
    \item \textbf{Imputation strategy}: Use median imputation for missing lags instead of dropping samples
    \item \textbf{Hyperparameter tuning}: Grid search River ARF parameters (n\_models, max\_depth, grace\_period)
    \item \textbf{Baseline comparison}: Implement simple online mean tracker to isolate ARF issues
\end{enumerate}

\paragraph{Long-Term}
\begin{enumerate}[nosep]
    \item \textbf{Multi-target extension}: Extend to receiving/rushing yards after passing yards validated
    \item \textbf{Hybrid architecture}: Integrate online learning with 5-way ensemble once baseline works
\end{enumerate}

\subsection{Conclusion}

Online learning validation revealed critical implementation failures across all four acceptance criteria. The framework (886 lines, 3 drift detectors, prequential evaluation) is production-ready from an architectural perspective, but empirical validation exposed fundamental data pipeline and configuration issues.

\textbf{Key findings:}
\begin{itemize}[nosep]
    \item \textbf{MAE 9× worse than target}: Online ARF achieves 535 yard MAE vs 60 yard target (likely data leakage)
    \item \textbf{0\% drift detection}: ADWIN/KSWIN/Page-Hinkley fired 0 times (insufficient data + wrong validation season)
    \item \textbf{250\% negative ROI}: Model degrades performance vs static baseline (catastrophic failure)
\end{itemize}

\textbf{Honest assessment:} This is a negative result demonstrating the difficulty of online learning for NFL player props. Sparse data (77\% sample loss), temporal dependencies (lag features), and drift detector tuning complexity make this a challenging problem requiring additional research.

\textbf{Next steps:} Complete debugging protocol (data pipeline audit, synthetic drift testing, hyperparameter tuning) before attempting dissertation publication or production deployment. Expected timeline: 2-3 weeks for full validation on 2020-2024 seasons.

\textbf{Value of negative results:} Publishing this failure prevents future researchers from repeating our mistakes. The detailed failure analysis (data leakage, insufficient samples, configuration issues) provides a roadmap for successful implementation.
