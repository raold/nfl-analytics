\paragraph{Feature Temporal Safety.}
Features marked \texttt{asof\_safe} (\checkmark) are guaranteed to use only information available before game kickoff. All 386 production features are validated by 15 unit tests and 2 runtime validators (see \Cref{app:leakage_audit}). The 7 target variables (\ding{55}) are post-game outcomes used only as training targets or evaluation metrics, never as predictors.

\paragraph{Disabled Features (Not in Production).}
Two experimental feature groups were disabled after A/B testing revealed negative signal (ADR-015):
\begin{itemize}
    \item \textbf{Kalman EPA Filter (18 features):} Team EPA regime detection with CUSUM---disabled due to $-10.2$ percentage point accuracy drop in holdout testing.
    \item \textbf{GP Injury Recovery (17 features):} Gaussian process recovery curves---disabled because underlying GP models never successfully trained on available data.
\end{itemize}
These features remain in the codebase with \texttt{weight=0.0} in \texttt{py/config/feature\_weights.yaml} for potential future iteration.

\paragraph{Feature Engineering Rationale.}
The feature catalog balances three principles:
\begin{enumerate}
    \item \textbf{Temporal safety}: Strict as-of semantics prevent leakage (validated by automated audit)
    \item \textbf{Interpretability}: Each feature has clear definition, calculation method, and domain motivation
    \item \textbf{Empirical validation}: Features are retained only if they demonstrate positive signal in A/B testing
\end{enumerate}

For detailed definitions of all 386 features, see the feature modules in \texttt{py/features/} and the unified extraction interface via \texttt{GameFeatureExtractor}.
