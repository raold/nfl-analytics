\paragraph{Feature Temporal Safety.}
Features marked \texttt{asof\_safe} (\checkmark) are guaranteed to use only information available before game kickoff. These are validated by 15 unit tests and 2 runtime validators (see Appendix~\ref{app:leakage_audit}). The 7 unsafe features (\ding{55}) are post-game outcomes used only as training targets or evaluation metrics, never as predictors.

\paragraph{Feature Engineering Rationale.}
The feature catalog balances three principles:
\begin{enumerate}
    \item \textbf{Temporal safety}: Strict as-of semantics prevent leakage (validated by automated audit)
    \item \textbf{Interpretability}: Each feature has clear definition, calculation method, and domain motivation
    \item \textbf{Redundancy control}: Rolling windows (last 3/5 games) provide recent signal while expanding averages capture long-term trends
\end{enumerate}

For detailed definitions of all 170+ features, see the feature catalog at \texttt{py/features/catalog.yaml}. Key ablation results showing the marginal contribution of each family are presented in \Cref{tab:ablations} (Chapter 4).
